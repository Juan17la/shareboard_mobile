The Metro Map design system

Shareboard is drawn as a small transit system: the board is the city, everything around it is signage. This page lists every token and component of the interface. Source of truth in code: mobile/src/constants/theme.ts, web/src/index.css, web/src/lib/theme.ts and the root DESIGN.md. See them in context in the mockups.

Principles

Board first

The canvas runs edge to edge; chrome is compact and floats on top.

One colour, one job

Blue acts and selects, green finishes, orange warns, violet marks app-wide places.

Solid signage

Opaque panels with full-contrast text over any drawing. No glass, no blur.

Two worlds

UI chrome and board content have separate fonts and palettes and never borrow from each other.

Interface colour

A white-and-ink signage ground carrying four saturated transit lines. A screen shows only the lines it needs.

Do and don't

Do
  • Give each line colour one job.
  • Cap every sheet with the 5 px ink rule; draw sections as stations on a coloured line.
  • Ring tappable circular controls in a 2 px ink border; keep targets ≥ 44 px on touch.
  • Set codes, PINs and numbers in JetBrains Mono with 1.5 px tracking.
  • Keep panels opaque with soft ink-tinted shadows.
  • Land every token change in mobile theme.ts, web index.css and theme.ts together.
Don't
  • Use translucent or blurred glass panels.
  • Use board fonts (Nunito, Lora, Caveat) or the drawing palette in UI chrome.
  • Fill a button with orange or violet.
  • Introduce a second blue or a system face.
  • Rely on colour alone for status.
